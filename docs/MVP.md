## Build order

1. Align on scope, stack, and data/API contract.
2. Build a tiny end-to-end journey with sample data.
3. Deploy it and share the URL with the entire team.
4. Replace sample behavior with the core feature.
5. Check empty states, invalid input, errors, and loading states.
6. Rehearse and prepare a backup demo before submission.

## Done means

The core journey runs from a clean checkout using the README, works at the deployed URL, handles its main failure case, and can be explained in the allotted pitch time. Known limitations are documented. All required submission fields are ready.
