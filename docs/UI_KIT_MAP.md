# HomeBeacon UI kit map

Which real ARGUS kit part builds which HomeBeacon screen element. Every name and signature below was read from `ui/kit/vendor/js/kit/*.js` (same bytes as the source library) or the library registry. Nothing here is invented. Library source (read only): `/Users/ayanbasheer/rion-nexus-worktrees/ui-library`.

## 0. Ground facts

- Vendored kit: `ui/kit/vendor/` (untouched). Retheme only through `ui/kit/theme-homebeacon.css` (generated by `ui/kit/tools/make-theme.mjs`). Glue: `glue.css`, `shims.js`. New parts: `ui/kit/hb/` (section 5).
- **Runtime gap.** `ui/kit/runtime.js` imports only `core`, `components`, `forms`, `motion`. This map also needs `table.js` (ArgusTable), `chart.js` (Kit.chart), `balance.js` (Kit.balance), `guide.js` (Kit.guide), `help.js` (Kit.helpBanner). The gallery entry already loads them. Add the five imports to `runtime.js`, in the gallery's order.
- **Lookalike gap.** The live screens call only nine factories today (confirm, select, popUpWindow, details, sectionBox, pill, foldOpen). Everything else is raw markup that `product-kit.js` dresses with `kit-*` classes. The plan below replaces that markup with factory calls.
- Rules of the kit: a `.kit` root; light is `body.light-mode`, dark is its absence; text is set with textContent, never innerHTML; no colour literals, tokens only; class names may not contain `card`, `tile`, `panel` or `-page`.
- Icons: `Kit.glyph(name | ['M..',...], { size: 14|16|20, cls })`. Named set includes alert, check, chevron*, close, copy, download, filter, gear, grid, info, list, pen, plus, search, sliders, star, store, trash, user. There is no map, pin or layers glyph: pass path arrays. `Kit.sectionMenu` icons must be path arrays.
- Honest states: `Kit.region(host, { what, skeleton: 'kpi-row'|'table'|'list'|'block'|'form', load, isEmpty, render, empty, unread, notSetUp })` paints exactly one of loading, loaded, empty, failed, not set up. It drops a stale run when a newer one starts. Failed never shows a create button.

## 1. Operator command center

Layout, region first. Dark theme is the default feel (the ARGUS Ops console: graphite surfaces, mono numbers, 8px controls, 6px tags).

```
rail | top strip: logo | mode tag | live counts | feed freshness | search | account
52px |---------------------------------------------------------------
     | NEXT STEP banner (one line, one button)
     |-------------------------------------------+-------------------
     | MAP, fills the space                      | Areas list (P1 first)
     | [Layers] [Base map] [Time]   legend       | "Suggested follow-ups"
     |-------------------------------------------+-------------------
     | dock: Live feed | Logs | Sent messages
drawer: Kit.sideSheet slides over the right column on selection
```

- **Rail.** `Kit.sectionMenu` collapsed (52px glyph column): Map, Areas, Homes, Messages, Zones, Activity. Footer `Kit.keyHints`.
- **Top strip.** `Kit.figureRow` for live counts (reporting, offline, critical, hotspots), counted up with `Kit.motion.countText`. Freshness is one `Kit.statusDot` per feed (ok, stale, error, needs_key, unverified map to ok, warn, bad, muted, info) with `Kit.hoverTip` for age and attribution. When polling backs off the dot turns warn and says so. Mode (Live or Exercise) is `Kit.plainTag`.
- **Map.** MapLibre stays. Controls sit on it: Layers popover (`Kit.filterButton`), Base map (`Kit.inlineSwitch`), Time (scrubber, hb). Legend lists all five risk words, each with its dot, so colour is never the only signal.
- **Areas list.** `ArgusTable` grouped by tier with `groupBy`. Switch Areas, Homes, Follow-ups with `Kit.inlineSwitch`. Rows update in place on every 4 s poll with `t.update({ rows })`. A status change pulses the row, gated by `Kit.motion.changed(key, status)`. The pulse CSS is ours (hb).
- **Drawer.** `Kit.sideSheet` (non-modal, 400px, no scrim) holding `Kit.subTabs`. A home has Overview, Sensors, Risk reasons, Logs, Messages, Customer. An area has Overview, Homes, Messages, Logs. Each pane is its own `Kit.region`, so a slow tab never blanks the others.
  - Overview: `Kit.details` plus an advisory `Kit.notice` ("Advisory only. A person must review this.").
  - Sensors: `Kit.chart` area per sensor (60 min), `Kit.missingFigure` when under two points, stale readings tagged with `Kit.plainTag`.
  - Risk reasons: one row per reason with `Kit.statusDot` and the plain sentence, evidence behind `Kit.showMore`. Stale critical keeps its "last reported 40 min ago" text.
  - Logs: `Kit.listToolbar` (search, level, range) over the hb log viewer.
  - Messages: `ArgusTable` with a state badge (queued, delivered, acked, expired, cancelled). Cancel goes through `Kit.confirm`.
  - Customer: `Kit.details` (linked, contact name, consent), then the help-status control.
- **NEXT STEP banner.** `Kit.notice` with one action, re-`show()`n in place. A pure function picks the single message: no devices, then hotspot, then a stale feed, then exercise mode. Eyebrow and tone rail are an optional hb part.
- **Suggested follow-ups.** `Kit.guide`, `compact: true`, items from `followUps()`: P1 becomes `now`, P2 `soon`, P3 `tip`. The `why` is the risk reason text. One action: Open home. `done` appears only when the risk read succeeded; if it failed, pass `failed: true`, never "all caught up".
- **Send message.** `Kit.popUpWindow`, size `lg`. Scope, kind and severity use `Kit.pickOne` or `Kit.select`. Title and body use `Kit.field` with `Kit.input` and live 20 and 80 counters in the field help. `requiresAck` and `customerVisible` use `Kit.switch`. An hb OLED preview (21 by 8) sits under the form. Urgent or region sends ask `Kit.confirm` first. Success is `Kit.notify`.
- **Help status.** `Kit.pickOne` inside `Kit.settingRow`, with a 140-char note. Confirm before `resolved` because the household sees it. Row shows `saving()`, `saved()`, `error(msg, retry)`. History is `Kit.historyList`.
- **Bulk bar.** `ArgusTable` `selectable`, then `Kit.selectionBar`: Send message, Clear. Server fan-out is capped at 200 devices, so say so when the selection is larger.
- **Undo.** `Kit.undo` only for the reversible zone hide (re-PATCH `active:true`). Messages and help status are not undoable, so they confirm instead.
- **Save notes.** `Kit.saveNote` beside every notes field.
- **Empty and could-not-load.** `Kit.region` or `ArgusTable` `state`. A 404 or 503 from a new API reads "Not available yet" via `Kit.missingFigure({ reason })`. A feed with `needs_key` uses `Kit.notSetUp`. Words differ for empty, failed and not set up, always.
- **Boot.** `Kit.openingScreen({ caption: 'Opening HomeBeacon' })`, `s.say(text)`, `s.leave(done)`.

## 2. Customer portal (mobile first, calm)

Single column, max 560px, no rail, no motion beyond the kit's own. Everything refreshes in place every 20 s.

- **Top.** `Kit.logoLockup`; Sign out is a `kit-quiet` button.
- **Device.** `Kit.sectionBox` titled with the nickname. Body: `Kit.statusDot` plus the server's `statusText` (normal green, needs_attention warn, urgent bad, no_recent_signal muted, always with words), "Last heard from you" line, conditions in `Kit.details` (label, value). Exercise devices get a `Kit.plainTag`.
- **Messages.** One `Kit.sectionBox` per active message (`tone: 'danger'` for urgent, `'quiet'` otherwise), `desc` = body, `actions` = a **Got it** `kit-everyday` button. Failure shows `Kit.saveNote` error with retry.
- **Help status.** `Kit.historyList` titled "Help from the team". The customer API returns only the current status today. Ask for a customer-safe `help.history` (status, time, no operator names). Until then, show the current step plus note.
- **Claim by QR or serial.** `Kit.inlineSwitch` (Link a device, I have an account). Fields: `Kit.field` + `Kit.input` for serial, 6-digit code (prefilled from `#claim=`, shown with a `Kit.plainTag` "From your QR code"), nickname, name. Consent and terms are `Kit.tickBox`. Submit is `kit-main-action`. Errors use the uniform sentence in `Kit.field` error. Success is `Kit.goodNews`.
- **More.** "Link another device" is `Kit.foldOpen`. Unlink is `Kit.confirm({ danger: true })`. No devices is `Kit.empty`. Loading is `Kit.region`. There is no in-app QR scanner: the phone camera opens the link.

## 3. Public marketing site

- **Header.** `Kit.logoLockup`, nav links, mobile `Kit.buttonMenu`. Skip link `kit-skip-link`.
- **Hero.** Headline, two actions, then the **signature piece: an interactive neighborhood scene** (hb). Homes are focusable buttons. A home shows `Kit.statusDot` and opens `Kit.hoverTip`; selecting one opens `Kit.sideSheet` with a simulated `Kit.chart`. Controls: `Kit.inlineSwitch` for scenario (Quiet, Storm, Outage), `Kit.slider` for time. Everything is tagged "Simulated" (`Kit.plainTag`). Autoplay only if `Kit.motion.canMove()`, started by `Kit.motion.whenSeen`. Reduced motion leaves a still scene with the step button. The current `/demo` iframe stays as fallback.
- **Signals.** `Kit.details` (Power, Wi-Fi, Water, Nearby disasters).
- **How it works.** Three `Kit.sectionBox` with `Kit.numberBadge`, cascaded with `Kit.motion.delayFor`.
- **Neighborhood view.** `Kit.listBox` ("Areas to check first", share bars) and `Kit.chart` kind `bars-by-hour` ("Reports per hour, simulated storm"). `Kit.balance` for one counted-up headline. `Kit.sparkline` in rows.
- **Device.** `Kit.details` for the five specs, plus an hb stage trail (Home box, Local hub, Shared map) from the Ops wiring map.
- **Limits.** `Kit.sectionBox` `tone: 'quiet'`: no occupancy, damage or safe-entry claims.
- **Start here.** Three `Kit.clickBox` doors with `href` and `go: 'Start'`.
- Motion note: `Kit.motion.reveal` only has CSS for `kit-guide` and `kit-help`. Other reveals need hb CSS.

## 5. Parts the kit lacks (build under `ui/kit/hb/`)

Convention: `ui/kit/hb/<part>.js` plus one `hb.css`; register as `Kit.hb.<name>` with a flag so a second load is a no-op; import from `runtime.js` and `kit.entry.js`; add each to the gallery. Anatomy: `Kit.el` only (no innerHTML), tokens only (`--kit-*`, nothing literal), radii `--kit-r-ctl` 8px and `--kit-r-tag` 6px, durations `--kit-dur` and `--kit-dur-panel` with `--kit-ease`, focus ring `outline: 2px solid var(--kit-accent)`, hover, focus and pressed states, 44px touch floor, a reduced-motion block last (`html[data-motion='reduce']` and `prefers-reduced-motion`), class prefix `kit-hb-`, no `card`, `tile`, `panel`, `-page` in names. Icons from `Kit.glyph` with path arrays.

1. **Map controls**: zoom in and out, reset north, fit to homes, full view, as grouped `kit-icon` buttons. Also the zone draw bar.
2. **Layer list** (overlay toggles): swatch, name, switch, status dot, data age, opacity (`Kit.slider`). Ship v1 from `Kit.settingRow` + `Kit.switch`; build this only for the legend and opacity.
3. **Timeline scrubber**: `Kit.slider` with a time `format`, play and pause, speed, event ticks, a Live button. Needs a history read; `/api/ops/live` has a cursor only, and `/api/ops/device` has 60 minutes per sensor.
4. **Log viewer**: mono rows with time (ArgusTable's date type shows the day only), level tags, follow and pause, copy line (`Kit.copyIcon`), jump to time.
5. **Map marker, cluster, hotspot ring**: status word on the marker, pulse when `Kit.motion.changed`.
6. **OLED preview**: 21 by 8 mono screen.
7. **Next step banner** (optional): eyebrow, tone rail, one action, from `ao-wiring-next`.
8. **Stage trail**: numbered stages, status pill, connector with a travelling pulse once both ends are live, from `ao-wiring-flow`. Serves the help timeline and the marketing device path.
9. **Neighborhood scene**: the marketing signature piece.
