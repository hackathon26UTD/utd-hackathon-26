## Product goal and boundaries

A black box at a house records power, connectivity, battery and available environmental observations, retaining original timestamps while offline. A local gateway can forward records when a path exists. A command center helps operators review which homes or neighborhoods need a check and document follow-up.

Response priority is not a damage probability. A sensor report does not establish safe occupancy, structural safety, claim coverage, a payout or an emergency dispatch. Missing data is unknown. Old critical observations remain visible as last-known critical rather than becoming safe. Human evacuation reports must be explicit and sourced. PIR inactivity does not prove absence.

Ayan also asked for hardware-first ideas with a real problem and a potential startup moat, and challenged ideas that a phone could replace. The product case to test is permanent unattended home observations, local outage records and an insurer/recovery workflow. A defensible moat or superior resilience has not been demonstrated. Research real operator decisions, sensor coverage, installation friction, false alarms and willingness to adopt before treating an LLM/map as differentiation.

The original edge-model proposal was selective load shedding: reduce camera/display/radio or sample rates according to battery and severity while preserving useful records and critical reports. Actual power budgets, rules, model necessity and critical/noncritical behavior remain hardware decisions to validate with Dhruv. Do not claim an edge model currently controls the physical box.

The proposed State Farm value is a more specific picture for catastrophe outreach, inspection planning and regional response. It is not an existing State Farm integration. The exact current challenge prompt and complete sponsor-track inventory have not been verified in this workstream. Obtain the official prompt before claiming exact alignment.

## What is shipped

### Public experience

- `/`: full public marketing homepage, not the sign-in screen.
- Sticky top navigation: how it works, command center, hardware, exercise and portal.
- A custom illustrated neighborhood scene with power/water/reconnection states, signal transport, manual scenario controls, play/pause and pointer perspective.
- Staged entrance motion; reduced-motion support stops animations. Scenario labels are text, not color alone.
- Product sequence: observe, retain locally, review at the command center.
- Real command-center screenshot, a hardware concept cutaway, practical FAQ and entry calls to action.
- `/portal`: session-aware redirect to `/command-center` or `/login`.
- Site icon, metadata, legal footer and public map/font licenses.

### Command center

- Real MapLibre/OpenFreeMap street map and accessible list alternative.
- Exercise data is synthetic, prominently marked, and never seeded as real devices.
- Live summaries from MongoDB; 30-second refresh while the page is visible.
- Search, priority filters, selected-home observations and timestamps, follow-up recording, JSON export of the visible view.
- Weather source status and a toggle for official NWS polygons where geometry is available. Many official alerts have no polygon; this is not an all-hazards live raster radar product.
- Observation layers can be previewed, applied to map/list, and cleared. Supported predicates: water, power loss, Internet interruption, stale reports, low battery, critical observations.
- Demo event sequence is an exercise story. It does not prove physical offline replay or a connected box.

### Accounts and policies

- Server-side password verification, signed secure HTTP-only eight-hour sessions, same-origin writes, sign-out, login throttling and session revocation after a password change.
- Basic operator profile, password change and single-use recovery code reset.
- Email reset delivery, general sign-up, team invitations, SSO, MFA and a multi-tenant authorization model are not implemented.
- Shared demo account is intentionally public on `/login`; it can use exercise records and preset layers only. It cannot read live devices, change accounts, write follow-ups or spend NVIDIA quota. Its profile is read-only.
- Terms, privacy, cookies and accessibility statement exist. No analytics or advertising is installed. Cookie preference actions both preserve essential-only storage.
- Legal copy is a prototype draft; manual assistive-technology and legal review remain necessary.

### NVIDIA command layer

- Server endpoint `/api/layers` supports preset views and a future NVIDIA NIM/OpenAI-compatible model endpoint.
- Configure encrypted `NVIDIA_API_KEY`, optional `NVIDIA_MODEL`, or an administrator-trusted `NVIDIA_BASE_URL` for a team-hosted compatible model.
- No key or endpoint was found/configured in this session. The user explicitly approved building for later connection.
- Default model identifier is recorded in `docs/OPERATOR_LAYERS.md` and the implementation; verify availability when connecting.
- Sends bounded latest sensor values and timestamps for up to 500 boxes, excluding addresses, operator emails, credentials and free-text notes. This is not the entire raw database history.
- Model must choose one to three supported predicates with all/any logic. Server computes matching homes from readings; model text remains interpretation requiring review.
- Four requests per minute per operator; 40-second upstream timeout. No arbitrary Mongo queries, model-supplied code, source-data mutations or automatic dispatch.

## Hardware facts and research constraints

The original discussion considered Raspberry Pi Pico or Pi 5 for size/spec fit. Current hardware planning in `docs/HARDWARE.md` instead lists ESP32-S3 Sense, a second ESP32, an Arduino Uno Q gateway, microSD, button, sound sensor and buzzer as team-owned. The HARP cart/request contains additional sensors/power parts; approval, checkout and actual wiring must be verified rather than inferred from a filled form.

No LoRa was available in that inventory; ESP-NOW is the short-range stand-in, not equivalent long-range coverage. No air-quality/gas sensor was available in HARP; sound/flame are limited proxies, not certified smoke sensing. AA backup, power regulation, GPIO voltage dividers, timestamp RTC and scarce S3 pins all need physical validation. Battery backup does not create an internet path. Never infer a vacated home from PIR inactivity.
